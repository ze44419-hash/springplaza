# إدارة القاعة والمحاسبة — دليل التنفيذ

إضافة جديدة فوق نظام سبرينج بلازا: **حجز القاعة بحاسبة تكلفة إلكترونية**، و**محاسبة** تدمج الكافيه والقاعة، و**توزيع أرباح الشركاء**.
كل الإضافات «إضافية» (additive): لا تعدّل جداول الكافيه ولا دوال البيع، وتم اختبار الـ SQL على PostgreSQL حقيقي (حجز مكرر، انتقالات الحالة، تجميد الأسعار، التقريب، تقاطع الفترات، صلاحيات RLS).

---

## 1) خطوات التركيب

1. نفّذ في **Supabase → SQL Editor** بالترتيب، **كل ملف في تشغيل منفصل**:
   1. `005_roles_accountant_hall.sql` — يضيف الدورين (لازم ينجح ويُحفظ قبل اللي بعده؛ PostgreSQL ما يسمح باستخدام قيمة enum جديدة في نفس المعاملة).
   2. `006_hall_accounting.sql` — الجداول والدوال والصلاحيات.
   3. `007_hall_seed.sql` — (اختياري) بيانات تجريبية للأسعار.
2. من الأدمن ← **الحسابات** ← أنشئ حساب بدور «محاسب» وآخر بدور «مسؤول القاعة».
3. شغّل `npm install && npm run build` كالعادة. لا توجد متغيّرات بيئة جديدة ولا مكتبات جديدة.

> منطقة التوقيت المستخدمة في حساب «اليوم» للتقارير هي `Africa/Cairo`، وتُغيَّر من مكان واحد: الدالة `_biz_tz()` في `006`.

## 2) الأدوار والصلاحيات

| | أدمن | مسؤول القاعة | محاسب | كاشير / كابتن |
|---|:-:|:-:|:-:|:-:|
| تقويم الحجوزات وإنشاء/تعديل حجز | ✅ | ✅ | عرض فقط | ❌ |
| تعديل أسعار الإيجار والأطباق والخدمات | ✅ | ✅ | عرض فقط | ❌ |
| المصروفات | ✅ | ❌ | ✅ | ❌ |
| الشركاء وتوزيع الأرباح وتقارير الحسابات | ✅ | ❌ | ✅ | ❌ |
| أوردرات الكافيه والمخزون | ✅ | ❌ | ❌ | حسب دوره |

- التوجيه في `src/middleware.ts` (جدول `ACCESS`): `/hall` للأدمن + مسؤول القاعة، `/accounting` للأدمن + المحاسب. كل دور يهبط على شاشته (`/hall` أو `/accounting`) بعد الدخول.
- **الحماية الحقيقية في قاعدة البيانات (RLS + الدوال)** وليست في الواجهة فقط. كمان `orders_block_non_cafe` (trigger) يمنع الدورين الجدد من إنشاء أو تعديل أوردرات الكافيه.

## 3) قاعدة البيانات

| الجدول | الغرض |
|---|---|
| `hall_rates` | خيارات إيجار القاعة (اسم + سعر + نشط + ترتيب) |
| `hall_services` | الأطباق (`kind='dish'`) والشوك/الخدمات الإضافية (`kind='extra'`: ديكور، إضاءة، دي جي، أدوات…) |
| `hall_bookings` | الحجز: التاريخ، العميل، الحالة، **لقطة الأسعار**، الإجمالي، المدفوع |
| `hall_booking_items` | بنود الحجز (اسم وسعر وكمية لحظة الحجز) |
| `expenses` | المصروفات: تاريخ، بند، يخص (كافيه/قاعة/عام)، مبلغ |
| `partners` | الشركاء ونسبهم المئوية |
| `profit_distributions` + `profit_distribution_lines` | توزيعات الأرباح المعتمدة (لقطة ثابتة لا تتغير) |

**منع تعارض الحجوزات:** فهرس فريد جزئي `hall_one_booking_per_day (event_date) where status <> 'cancelled'` — يستحيل حجزان فعّالان في نفس اليوم حتى لو ضغط جهازان في نفس اللحظة. إلغاء الحجز يرجّع اليوم متاحًا.

**حالات الحجز:** `pending` (مبدئي) ← `confirmed` (مؤكد) ← `completed` (تمت وتحصّل المبلغ) ، ويمكن الإلغاء من المبدئي أو المؤكد.

## 4) منطق الـ Backend (دوال Supabase RPC)

| الدالة | وظيفتها |
|---|---|
| `hall_quote(p)` | حساب تكلفة الحجز على السيرفر بدون حفظ |
| `hall_save_booking(p)` | إنشاء/تعديل حجز: يتحقق من التاريخ، **يعيد حساب كل الأسعار**، يحفظ اللقطة |
| `hall_set_booking_status(id, status)` | تغيير الحالة (انتقالات مسموحة فقط). `completed` يساوي المدفوع بالإجمالي |
| `accounting_summary(from, to)` | الإيرادات/المصروفات/الصافي/اليومي/حسب البند/معاينة حصص الشركاء |
| `distribute_profit(from, to, note)` | اعتماد توزيع الأرباح وحفظه |

**معادلة الحجز** (`_hall_compute`):

```
الإجمالي = إيجار القاعة + Σ(كمية الطبق × سعره) + Σ(كمية الخدمة × سعرها) − الخصم
```

- العميل بيشوف نفس الحساب فورًا في المتصفح (`computeQuote` في `src/lib/hall.ts`) لكن **السيرفر هو المرجع** ويعيد الحساب عند الحفظ، فلا يمكن التلاعب بالأسعار من الواجهة.
- **تجميد الأسعار:** تعديل الأسعار من لوحة الأسعار يسري على الحجوزات الجديدة فقط؛ الحجز المسجّل يحتفظ بسعر الإيجار وأسعار الأصناف اللي اتسجلت فيه (حتى عند تعديله)، والصنف الجديد المضاف إليه فقط يُسعَّر بالسعر الحالي.

**معادلة الأرباح:**

```
صافي الربح = (إيرادات الكافيه + إيرادات القاعة) − المصروفات
حصة الشريك = صافي الربح × نسبته %
```

- **إيراد الكافيه** = الأوردرات المدفوعة (`completed`) حسب وقت الدفع.
- **إيراد القاعة** = الحجوزات بحالة `completed` حسب **تاريخ المناسبة**. (قرار محاسبي: الحجز المبدئي/المؤكد لا يُحسب إيرادًا حتى يتحصّل. لو عايز تحسب المؤكد كمان، غيّر شرط `status = 'completed'` في `_acc_totals` و`accounting_summary`.)
- **التقريب:** كل حصة تُقرَّب لقرشين، وآخر شريك يأخذ فرق التقريب بحيث **مجموع الحصص = الصافي بالضبط**.
- **ضوابط اعتماد التوزيع:** مجموع نسب الشركاء النشطين = 100% بالظبط، صافي الربح موجب، والفترة لا تتقاطع مع توزيع سابق (منعًا لصرف نفس الربح مرتين).

## 5) الواجهة (الملفات الجديدة)

```
src/app/hall/                 layout + page.tsx (التقويم والحجوزات) + hall.module.css
```

## 7) حدود معروفة

- التقويم على مستوى **اليوم** (حجز واحد لكل يوم). لو القاعة بتستقبل أكتر من مناسبة في اليوم (صباحي + مسائي)، نحتاج نضيف فترات زمنية للحجز — اطلبها وأعدّل الفهرس والدوال.
- شاشات القاعة والمحاسبة تحتاج إنترنت (مثل شاشة المدير) ولا تعمل أوفلاين.
- لم أجرّب الواجهة على Supabase حيّ؛ اتفحصت بـ `tsc` (بدون أخطاء) واتختبرت دوال SQL على PostgreSQL محلي. جرّب الشاشات على مشروعك قبل الإنتاج.
